# Spec Delta

## Purpose

定义用户发送后的即时反馈、正文展示与数据库保存并行的可测量响应及恢复边界，避免空对话页面等待。按 2026-10-13 用户确认，生成中已显示正文可以暂未保存；完成必须确认全部保存，刷新或服务崩溃只恢复已保存部分，停止、删除和用户切换不得复活旧生成。

## ADDED Requirements

### Requirement: 即时提交反馈
系统 SHALL 在有效提交后 100ms 内显示用户消息预览和助手提交状态，不等待网络或数据库成功才显示，不在新对话创建后闪现空对话欢迎页。

#### Scenario: 慢建对话与慢生成提交
- **WHEN** 创建对话、生成提交或首字分别延迟数秒
- **THEN** 消息预览立即可见；提交成功前表示正在提交，确认后表示等待模型响应，不虚称已保存或已收到正文

#### Scenario: 拒绝与不确定提交
- **WHEN** 创建失败、生成被拒绝或请求断开而提交结果不确定
- **THEN** 给出明确状态并保留可恢复输入；通过原消息和生成 ID 对账，不重复用户消息，不使用普通失败重试覆盖未确认的提交

### Requirement: 流式响应与渲染
系统 SHALL 将当前活动生成的有效正文增量送入有界保存队列并向浏览器发送，发送不等待对应数据库写入完成；浏览器合并增量并只更新必要的展示内容，不重复渲染所有历史消息或为每个字符重复执行完整代码高亮。delta 表示当前会话收到正文，不表示正文已持久化。

#### Scenario: 受控流式基准
- **WHEN** 已预热仿真上游持续每 50ms 输出正文，使用独立测试 schema，并测量单次持久化往返
- **THEN** 在保存队列未饱和的固定场景中，上游正文到服务端 Flush 的延迟 p95 不超过 100ms，不随每批数据库往返增加；分别报告浏览器展示、数据库持久化、发送与保存的进度差及结束等待，交付原基线比较。发生背压时报告全部样本和饱和区间，不丢弃慢样本以声称达标

#### Scenario: 长内容与首字
- **WHEN** 输出包含两万字符、代码块、表格和较多旧消息
- **THEN** 首个正文不等待凑满大批次；预热后增量渲染耗时 p95 不超过 32ms，旧消息渲染次数不随每个增量增长，用户向上阅读时不被强制拉到底部

### Requirement: 持久化与终态完整性
系统 MUST 将正文发送与保存并行，数据库写入按生成内顺序串行执行，使用有界队列和合并批次。初始消息对和生成快照仍须原子保存后才开始上游生成；全部已接受正文和 completed 终态保存成功后才发送 done。生成中正文属于实时展示，不能把 delta 当作已保存确认。

#### Scenario: 写入缓慢与有界背压
- **WHEN** 数据库写入缓慢且生成持续输出
- **THEN** 在队列容量内展示不等待数据库，写入合并但不乱序；队列容量包含等待和正在写入的正文，达到上限时暂停接受新正文并向上游施加背压，不能无限积累或绕过容量继续显示新正文

#### Scenario: 正常完成或上游失败
- **WHEN** 上游结束或返回生成错误
- **THEN** 排空已接受的合法正文并保存相应终态后，再报告 done 或上游 error；保存尚未完成时不能虚称完成，最终成功正文与数据库完整内容一致

#### Scenario: 保存失败
- **WHEN** 正文或终态写入失败
- **THEN** 停止接受和发送新正文，停止上游并明确提示保存失败，不能发送 done；尽力保存 failed 终态，数据库不可用时仍须通过流错误或断流后的错误提示告知失败，不能将错误提示当作终态已落库确认。当前页面可保留已显示内容，刷新仅恢复数据库确认的部分

#### Scenario: 生成中刷新或服务崩溃
- **WHEN** 正文已经显示但部分尚未保存时刷新页面，或服务崩溃后重启
- **THEN** 只恢复最后已保存的正文与状态，未保存的显示尾段可能丢失；恢复的未完成回答按既有规则转 stopped，不自动重发或将尾段伪装为已保存内容

#### Scenario: 停止删除及迟到渲染
- **WHEN** 用户在提交前、首字前或流中停止，删除对话、退出、切换账号或服务重启
- **THEN** 停止上游及新正文发送，浏览器取消待绘制增量；停止和断连在有界收尾时间内尽力排空合法待保存正文，已删除或已终结的生成拒绝迟到写入。保存队列、待发送批次和迟到渲染均不能复活旧生成，原消息顺序、身份隔离和快照重试不变

### Requirement: 可追溯的性能证据
系统 SHALL 区分本地反馈、初始数据库提交、上游连接/首字、正文发送、正文持久化、结束保存等待及浏览器渲染的耗时；发送批次和保存批次可以不同，使用正文片段标识或累计偏移关联测量，不强制每个 Flush 对应一次已完成数据库写入。不将付费供应商思考时间或测试断言等待时间当作系统改进证据。

#### Scenario: 审核交接
- **WHEN** 实施者宣称修复发送或流式卡顿
- **THEN** 提供固定输入、仿真节奏、样本数量、数据库往返、p50/p95 和修改前后对比，日志不包含密钥、密码、完整会话或私人聊天正文
