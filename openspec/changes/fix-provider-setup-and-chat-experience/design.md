# Design

## Context

动机与授权边界见 proposal.md。基线为本地提交 `29483aa`；本变更当前只有规划，没有实施。此前 116 项 Go 测试、77 项前端测试、30 个浏览器场景通过，但用户本次反馈证明这些测试缺少真实模式菜单命中区域、供应商操作流程和流式性能断言。

已读取原参考 `test-results/screenshots/model-effort-menu.png`：输入框旁锚定主菜单，模型名称/说明/勾选，分隔线后是努力程度入口，子菜单在桌面侧向展开。该图为原 Mock 自动化生成的虚构内容，仅参考交互和几何；真实模式不得恢复其中的虚构连接。

用户供应商图的要求已转成文字：现有分类导航旁增加供应商列表，顶部添加按钮，右侧上部是当前供应商基础配置，下部是所属模型和拉取按钮。用户截图含私人账号，只作本地参考，不复制进 Git。

### 已确认事实与待测因素

| 问题 | 代码与观察证据 | 结论边界 |
| --- | --- | --- |
| 模型菜单变成弹窗 | `src/components/RealModelSelector.tsx` 使用 Dialog；原 `ModelSelector.tsx` 的 Dropdown/Sub 仍存在 | 是实施时主动改变了交互，可以直接恢复原菜单结构 |
| 设置只有文字附近能点 | `Auth.tsx` 的菜单项 asChild 为 Link；`styles.css` 的 menuitem 没有给链接块级整行布局 | inline 链接命中区域与其他菜单项不一致，应补实际坐标点击测试 |
| 供应商与模型割裂 | `Settings.tsx` 的 Providers 是全局卡片列表，Models 再选一次供应商，候选进入逐项编辑弹窗 | 数据关系已正确存储，主要重做工作区和批量操作流程 |
| 模型能力需手填 | `DiscoveredModel` 只有 ID/name；发现解析不保留输出上限或能力字段；候选不返回能力且新增表单固定 4096 | 缺少目录与能力解析衔接，不是只能让用户手填 |
| 截图 GLM 不识别 | 注册表有 glm 适配下的 `glm-5.3-flash`，没有 siliconflow 下的准确 `zai-org/GLM-5.3-Flash` 映射 | 可确定匹配缺口；具体合法硅基流动字段和档位仍需查官方文档，不能从名称推断 |
| 发送后空对话等待 | generation 协调器先 create、发布空对话并导航，再 await generate；消息在响应头返回后才进入视图 | 客户端可见反馈确实被服务端提交阻塞 |
| 流式有停顿 | 后端 200ms 批次先 await appendDelta；每批 BEGIN、两个 UPDATE、COMMIT，再 emit；前端每事件深拷贝全对话并更新历史，未 memo 的 MessageView 重解析 Markdown | 存在可确认的额外等待和重复工作，具体贡献须按阶段测量 |

只读数据库诊断（2026-10-11）：8 次预热后 SELECT 1 中位数 **90.2ms**；3 次 BEGIN/SELECT 1/SELECT 1/COMMIT 中位数 **375ms**。没有读私人表或调用模型。这是网络往返证据，不是 appendDelta 或完整聊天的实测耗时，也不能解释所有上游首字等待。实际模型的思考时间、代理缓冲、TLS/连接建立和浏览器长任务仍需分别计时。

## Goals / Non-Goals

**Goals:** 恢复原模型菜单；供应商上下文完成配置；自动解析与补全能力；立即提交反馈；在约 90ms 数据库往返下减少人为卡顿，并保持所有可靠性边界。

**Non-Goals:** 不接入附件、工具、知识库、共享密钥或管理员；不改数据库地址或迁移用户现有数据；不自动调用用户的付费模型；不放开未经核实的思考字段；不把尚未保存文本先当作持久正文发送；本轮规划者不直接实施。

## Decisions

### 1. 菜单恢复与点击区域

复用 `ModelSelector` 的 Radix Dropdown、RadioGroup、Sub 及 CSS，抽取可复用菜单外壳或让真实模式消费相同结构。数据仍来自用户模型 API。保留名称、描述和勾选；优先使用可信短描述，缺失时用供应商名/准确 ID，不写虚构性能宣传。

主菜单底部为“思考设置”或“努力程度”，按能力生成档位/开关/预算，预算用紧凑子面板，不重新引入整屏遮罩。较多模型允许搜索及列表内部滚动；未知能力显示简短提示。切换型号恢复该模型默认值；关闭菜单保留草稿和会话内选择。移动端继续沿用原防溢出策略，验证鼠标跨越主/子菜单、Tab、方向键、Escape 和触屏点击。

账号 Link 菜单项采用 block 或 flex、完整宽度和统一内边距，保持真实链接语义，不用只绑定文字的 click handler。浏览器测试通过行左/中/右实际坐标点击，不只用 getByRole 点击文字中心。

### 2. 供应商工作区

桌面建议分类导航 192px、供应商列表 224px、右侧详情弹性布局；1024px 列表可缩至 192px，主详情至少约 480px。沿用现有浅色变量、字体、细边框与橙色，不整体更换主题。右侧不要固定拉到截图红框高度，按内容自然布局。

列表顶部是“添加供应商”，下方为已添加供应商名称、启用状态和选中状态。详情上部直接编辑名称、模板、协议、地址、密钥与启用；下部展示已添加及待添加模型，提供拉取、搜索、批量添加/启用、单行启停、默认选择和原生参数编辑。未保存修改切换供应商时保留草稿或让用户明确保存/放弃；不能静默清掉。

保留“模型”分类作为全局汇总、跨供应商默认选择和筛选，不再要求用户在模型页二次选择供应商才能配置。路由可用 `/settings/providers/:providerId`，旧 `/settings/providers` 仍显示列表和安全默认详情；旧 `/settings/models` 继续可用。不存在或非本人 providerId 返回不存在。

768px 以下保留顶部分类；供应商列表/详情逐级切换，详情有返回列表入口，不能把三列压在手机上。表单、模型列表和错误信息在 390px 均可见。当前供应商选择和未保存草稿只属于当前用户；切换身份清空。

### 3. 内置目录与能力解析

新增可枚举的版本化内置模型目录，复用已有注册表而非维护两套互相矛盾的能力。每条记录区分 canonical identity、原上游 ID、明确 provider aliases、适用协议/adapter、能力及约束、安全默认输出值、默认思考行为、来源 URL、核实日期和版本。可保存为随服务发布的 JSON/Go 数据；启动不依赖在线下载。外部目录只能作为可选维护来源，若使用须核对许可证与字段可靠性，不能直接替代原生参数文档。

字段处理按如下规则：

1. 型号可用候选以本次真实上游返回为准；内置回退只表示可以尝试，不证明账号有权限。
2. 原生参数映射始终受 provider adapter 与协议限制。保存原始调用 ID，不随规范化而改写发给上游的 ID。
3. 显式支持的上游元数据优先补充名称、上下文/输出限制；能力字段必须有明确协议契约。Gemini 可解析输出限制和生成方法，OpenRouter 可解析已文档化 supported parameters；普通兼容 `/models` 只有 ID 时，不能凭空得到思考档位。
4. 已核实目录补齐缺失能力。别名逐条登记，覆盖用户截图型号时同时记录硅基流动的参数来源；不能任意删命名空间或大小写折叠。
5. 上游限制和内置约束采用合法交集，来源冲突明确提示。合法用户覆盖优先；变化不兼容时提示重置，不自动降档。

已知模型添加时自动填写名称、`min(4096, 可信输出上限)` 等安全默认值，思考参数默认 `{}` 表示供应商默认，强制思考按协议已有逻辑处理；不能把“自动设置”解释为默认开启最高强度。未登记模型仍可普通聊天，未知输出沿用保守上限；高级手动 ID 是最后入口。

### 4. 发现接口、回退与批量保存

保留现有 `/providers/:id/discover` 的数组契约，新增 `POST /api/providers/:id/model-candidates` 返回带来源的对象，新增 `GET /api/providers/:id/model-catalog` 提供该供应商兼容目录，两者都先校验当前用户归属。新界面使用前者；旧客户端及测试无需被迫接收不兼容形状。

建议候选响应包含 `source: upstream|catalog`、`catalogVersion`、安全中文 `warning`、`models`；每项包含原 ID、name、capabilities、recommendedDefaults、字段来源及 availability。上游能力元数据只保留允许公开的字段，不透传完整原响应或鉴权内容。

首次保存供应商成功后自动发现一次，后续显式“拉取模型”刷新；名称修改不反复触发网络请求。发现失败、401/403、超时及空列表都明确显示实际原因，再展示内置候选。已有已添加模型和最后成功列表不因失败丢失；列出内置项不代表连接成功。

按当前 providerId、配置 updatedAt/版本及目录版本缓存结果，前端 query key 包含用户身份和 providerId；切换、改地址/适配/密钥、退出失效对应缓存。迟到发现不能覆盖新供应商页面。后台缓存有限期且不存日志里的明文密钥。

批量添加复用统一模型校验逻辑，按 user/provider/native ID 去重，建议新增 `/providers/:id/models/batch` 返回逐项结果；一次操作不改写已存在模型的用户参数，也不把失败项假称为成功。默认模型仍须显式选择；停用供应商不改模型自身开关。

### 5. 立即反馈和提交对账

把“正在提交”的临时消息作为独立视图状态，不伪造数据库 completed 消息。点击后立即展示用户预览和助手占位，即使首页尚无服务端 conversationId；创建返回后将临时视图绑定真实对话，导航不经过空欢迎页。临时记录复用本次 userMessageId、assistantMessageId、generationId，成功响应按 ID 合并，不能再次 push 两条消息。

只在服务端确认提交后清理已发送草稿副本；失败能恢复且不能覆盖用户后来输入的新草稿。提交结果不确定时先读取已知对话按 generationId/messageId 对账，必要时增加按归属查询生成状态的只读接口，不能盲目新建消息或普通 retry。停止需取消本地状态与原请求，创建尚未返回时不调用上游，返回后也不能导航或复活预览。

协调器使用已加载对话或创建响应，避免为已有缓存无条件再 GET；缓存不是服务端权威，提交仍由数据库校验最新历史/活动锁。查询重取只更新服务端部分，不能覆盖正在提交预览。减少认证外额外读取，模型和供应商可合并归属查询；初始写入仍保持对话锁、消息对和快照原子性。

状态用“正在提交”“等待模型响应”“正在生成”区分。只收到思考数据、尚无正文时继续明确等待，不显示空页，也不伪造正文或思考内容。

### 6. 流式持久化与渲染

先保持保存后发送的契约，优先将每批 BEGIN/两次 UPDATE/COMMIT 改为一条原子 SQL，例如带条件与锁顺序的 CTE，减少数据库往返。SQL 必须绑定 user/conversation/assistant/generation、活动状态并检查实际影响行数；停止、删除、重试换 generationId 后旧批次不得命中。不要只合并语句而丢失这些条件；没有确认成功时不能 emit。

读取上游、积累正文与写入协调分离；每个 generation 同时只有一个持久化写操作和有界待写缓冲，保持顺序并合并相邻增量。短合并窗口先以 30–50ms 为调试起点，首段不等待大阈值；数据库慢时合并积累并背压，不能无限排队或并行乱序写。终结先排空合法批次，再保存元数据/终态，再发 done/error。停止和断连使用已有 durable context 收尾，未保存正文不发送；不新增异步丢数据的后台保存契约。

前端对已持久化增量按 animation frame 合并 UI 更新，停止/删除/退出取消待绘制任务；done/error 前将合法待绘制正文收敛，迟到帧按 generationId 和身份版本拒绝。保持消息引用与不可变更新，只替换活动助手消息；旧 MessageView memo，避免每事件 structuredClone 全历史、排序侧栏及完整历史重渲染。侧栏在创建/实际更新时间边界更新，首字与终态立即反映，不能为节流而破坏排序。

活动代码块先渲染安全文本或节流高亮，完整高亮留到稳定/终态；已完成代码缓存。Markdown 和复制结果保持正确，禁止 HTML。不使用假打字动画掩盖服务端停顿。

### 7. 验收指标与审查包

采样至少 30 次发送，仿真固定每 50ms 输出、含首字 0/500/2000ms 场景、20k 字符与代码/表格；HTTP 连接及高亮预热后测量。记录 t_click、t_preview、t_create、t_submit_commit、t_upstream_connected、t_upstream_first_text、t_delta_commit、t_flush、t_render。测试接口或观测代码不能进入生产密钥日志；不记录私人正文。

- 点击到消息预览不超过 100ms，在人为延迟 create/generate 两秒时也成立。
- 服务端有效正文到 Flush 的额外 p95 不超过一个持久化往返 p95 +100ms；往返不高于 100ms 时不超过 200ms，报告原实现比较。真实高延迟数据库另报告实际值，不能改成低延迟内存假存储后宣称已修复。
- 热身后增量渲染 p95 不超过 32ms；报告浏览器 long tasks、旧消息 render 次数、首字显示和 UI 更新次数；背景页降频不计入前台指标，但停止/恢复必须正确。
- 四协议、未知模型、目录回退、非法能力、两用户隔离、提交前停止、流中停止、断连、重启、删除不复活及原模型快照重试继续通过。

首字上游时间不由本系统保证。实网供应商速度未在本轮测量，不能将 375ms 诊断外推为全部卡顿原因。实际测量发现无法满足目标时提交原始证据与剩余瓶颈，不降低目标、关闭持久化或放宽测试来伪称完成。

## Risks / Trade-offs

- 聚合站别名变更 → 精确映射、版本和文档来源，未知参数不猜；允许普通聊天。
- 远程数据库 RTT 对严格保存后发送构成下限 → 减少往返与合并增量，展示明确等待，维持可靠性；同地区部署为后续建议，不在本变更换库。
- 乐观预览与服务端历史竞争 → 临时层分离、ID 对账、身份和 generation 版本拒绝迟到事件。
- 有界缓冲改变停止时序 → 保留原生命周期集成测试，新增写入阻塞时停止、删除、终结竞态。
- 三列挤压移动界面 → 列表/详情逐级导航及宽度断言，不用横向页面滚动解决。

## Migration Plan

先补六问题复现和测量，再菜单/点击区域、目录接口、供应商工作区、提交反馈、持久化与渲染优化，最后完整回归。若需保存解析能力或增加版本字段，新增 goose 迁移并验证独立 schema 上下迁移、运行 sqlc；不得改 `00001_initial.sql` 或重建 public。旧供应商、模型、默认参数与历史保留，新增候选接口不破坏旧 discover。

测试产物使用忽略目录，不能覆盖正在使用的真实服务 dist；若沿用当前 E2E 构建方式，结束必须重新 build:real。新变更 tasks 起始 0 完成，待另一智能体提交实施证据后原协作者独立审核；旧后端变更的完成记录是基线功能记录，不是本修复验收。
