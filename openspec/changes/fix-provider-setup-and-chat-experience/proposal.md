# Proposal

## Why

多供应商后端基线已经提交为 `29483aa`，但用户实际使用发现模型菜单偏离原设计、账号菜单点击范围过小、供应商与模型配置割裂、能力发现缺少回退，以及发送等待和流式卡顿。现有功能测试通过不能替代这些交互和性能验收，需要单独修复并提供可复核证据。

## What Changes

- 真实模型选择恢复输入框旁的下拉菜单和思考子菜单，沿用原模型菜单几何与交互，不再用居中弹窗。
- 账号菜单整行可点击，并验证键盘与触屏操作。
- 供应商页改为分类导航、供应商列表、当前供应商详情；添加入口移入供应商列表顶部，基础配置与所属模型列表同页操作。
- 模型发现形成上游列表、内置版本化目录、手动输入的回退链；保存后自动尝试发现，支持批量添加和启停，不要求逐个填写已知模型。
- 补全经过核实的模型与供应商准确别名映射，保留上游能力元数据，自动填写合法输出默认值并呈现原生思考控制；未知能力不猜测。
- 按 2026-10-12 用户反馈，参考 LobeHub 的供应商搜索、分组连接设置和紧凑模型管理交互，自主实现 Claude 风格的暖灰背景、克制边框、清晰留白与模型配置入口。全局模型页可直接进入所属模型设置，输出和思考信息始终可见。
- 区分用户设置的每次回复上限与模型可信最大输出，持久保存服务端发现的限值及能力元数据；刷新、重新登录与服务重启后仍供展示、模型保存校验和请求阶段使用。对供应商连接变更和迟到发现做失效保护。
- 发送立即显示本地用户消息和提交状态；减少冗余请求及串行数据库往返，保留失败恢复、提前停止及身份隔离。
- 按 2026-10-13 用户确认，正文增量向浏览器发送与数据库保存并行，展示不等待每批数据库写入；保存使用有界队列、顺序合并写入，全部正文和终态保存成功后才报告完成。保存失败明确提示，生成中刷新或服务崩溃只恢复已保存部分，最新显示的未保存尾段可能丢失。
- 分别验收正文展示延迟、持久化延迟和结束保存等待，增加可重复的长回答、停止及恢复测试，不把上游思考时间当作界面冻结。

## Capabilities

### New Capabilities

- `provider-workspace`: 供应商上下文中的配置与模型管理、账号菜单命中区域、真实模型下拉选择。
- `model-discovery-catalog`: 模型发现、内置目录回退、准确能力映射、默认值与来源管理。
- `chat-responsiveness`: 即时提交反馈、可靠持久化流式输出和可测量的渲染响应。

### Modified Capabilities

当前没有已归档的主规格。上述能力细化已有后端变更的交互与性能；已有用户隔离、停止和重试边界继续适用。用户明确要求覆盖原居中模型弹窗和分离配置流程，并在 2026-10-13 确认用正文发送与保存并行替代逐批保存后发送；本变更的新规格覆盖旧后端变更及历史交接中的保存后发送约定。初始用户消息、助手记录和生成快照仍须原子保存后才开始上游生成。

## Impact

涉及 React 设置与菜单、生成协调器、Markdown 渲染、Go 模型发现/能力注册表、生成 SQL 和测试。新增目录接口及发现响应扩展须同步前后端契约；本轮能力持久化追加 goose 迁移并重新生成 sqlc，不改已执行迁移。变更已部分实施，任务按实际验收保留完成或未完成状态。不导入用户截图或私人数据，不调用付费上游，不自动提交或推送后续修复，除非用户另行要求。LobeHub 只作交互与数据结构参考，不复制其代码、静态模型数据或品牌素材。

本次流式策略修订需同步 NDJSON 增量/完成/保存失败语义、前端恢复行为、保存顺序与背压测试，以及性能采样的显示/持久化关联方式。仅并行流式保存不要求新增数据库迁移；本次规划修订不表示实现或验收已经完成。
