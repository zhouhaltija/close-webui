# Spec Delta

## Purpose

定义真实后端中对话和消息的保存、流式生成、停止及失败重试，使已有前端聊天体验在服务端和第三方模型之间保持一致，并抵御并发、断连与迟到写入。

## ADDED Requirements

### Requirement: 服务端历史与原子提交
系统 SHALL 通过统一对话 CRUD 管理当前用户历史，按顺序保存消息，首次生成原子提交用户消息、助手占位和模型参数快照，同一对话最多一个活动生成。

#### Scenario: 并发发送
- **WHEN** 同一对话已有活动生成或重复提交同一生成 ID
- **THEN** 拒绝额外生成，不增加重复消息或产生第二次上游调用

### Requirement: 流式持久化
系统 SHALL 将四种上游协议转换为 delta、done、error NDJSON，先保存增量再发送，先保存终结状态再发送终结事件。

#### Scenario: 正常与异常终结
- **WHEN** 上游正常完成、报错或在终结前断连
- **THEN** 分别保存 completed 或 failed，保留部分回答，无终结事件的流不得视为成功

### Requirement: 确定性停止
系统 SHALL 使用独立生成 ID 幂等取消，处理提交前取消意图和连接关闭，停止上游工作并保留部分回答，迟到事件不能改变 stopped 状态。

#### Scenario: 提交前停止
- **WHEN** 停止请求先于生成提交到达
- **THEN** 后续同一生成 ID 不得调用上游或开始输出

#### Scenario: 删除与重启
- **WHEN** 删除生成中的对话或服务重启
- **THEN** 删除记录不得复活；重启后未完成回答转 stopped，不自动重发

### Requirement: 失败重试
系统 SHALL 仅允许重试最后的 failed 助手消息，保留消息 ID，以新生成 ID 和原参数快照替换失败内容，不重复用户消息。

#### Scenario: 重试及配置变动
- **WHEN** 用户重试失败回答或原配置已经不可用
- **THEN** 可用时重用原模型参数；不可用时明确报错，不使用当前菜单选中的其他模型
