# Spec Delta

## Purpose

定义 CloseWebUI 的中文聊天阅读与输入体验，使用户在桌面和移动设备上都能自然创建对话、阅读长回答并控制滚动。首页参考用户提供的 Claude 截图调整布局、比例和视觉层级，同时使用自身品牌、随机欢迎语及项目已实现的功能，保留可访问的交互与完整聊天行为。

## ADDED Requirements

### Requirement: 品牌与响应式布局
系统 SHALL 参考提供的 Claude 首页截图呈现中文浅色界面，使用 CloseWebUI 字标、橙色欢迎图形、随机欢迎语、真实历史侧栏和紧凑输入卡片，支持首页、侧栏和对话页。

#### Scenario: 桌面布局
- **WHEN** 用户在 1878×983 参考视口或 1440/1024 像素宽度访问应用
- **THEN** 系统显示可折叠侧栏、首页或对话内容和输入框，参考视口下主区域位置及尺寸与截图对齐，没有原先自创的欢迎副文案、建议卡片或页脚，无页面横向溢出

#### Scenario: 移动布局
- **WHEN** 用户在 390 像素宽度访问应用并打开侧栏
- **THEN** 侧栏以可关闭的抽屉呈现，关闭后恢复内容与输入区域，宽表格和代码仅在自身容器内横向滚动

### Requirement: 输入与发送
系统 SHALL 提供自动增高的文本输入框，阻止空白消息发送，支持 Enter 发送、Shift+Enter 换行及中文输入法选词，生成期间禁用再次发送并提供停止操作。

#### Scenario: 文本输入
- **WHEN** 用户输入多行文本并按 Shift+Enter
- **THEN** 系统插入换行，输入框随内容增长至设计的最大高度后内部滚动

#### Scenario: 空白与有效消息
- **WHEN** 输入仅为空格或换行，或用户在有效文本状态按 Enter
- **THEN** 空白输入不会产生消息或请求，有效文本只发送一次并在成功提交后清空输入框

#### Scenario: 中文选词
- **WHEN** 中文输入法组合输入期间用户按 Enter 确认候选词
- **THEN** 系统完成选词且不发送消息，组合输入结束后再次按 Enter 才发送

### Requirement: 已实现功能与模型标识
系统 SHALL 呈现聊天、历史管理、搜索、排序及模型/努力程度选择界面，默认显示 Sonnet 5.5 · 中等；不提供 Cowork、账户/付费、附件/语音或其他未实现服务入口，不将模型选择界面表达为真实模型连接。

#### Scenario: 首页控件
- **WHEN** 用户打开新对话首页
- **THEN** 输入区显示 Sonnet 5.5 · 中等标签和模型选择入口，空白时不显示发送，有效输入可发送，等待和输出期间显示停止，界面没有其他未实现功能的可点击占位入口

#### Scenario: 模型与努力程度选择
- **WHEN** 用户打开模型菜单或努力程度子菜单并选择项目
- **THEN** 系统显示名称、说明与当前选中标记，更新输入区标签，保留草稿及当前欢迎语，导航到聊天后选择仍保留，菜单支持键盘及焦点恢复且不越出窄屏视口

#### Scenario: 无商业套餐内容
- **WHEN** 用户查看模型菜单和努力程度子菜单
- **THEN** 系统不显示更多模型、Pro/Max、升级、额度、套餐或用量提示，模型回答仍遵循首版 Mock 的固定场景

#### Scenario: 历史搜索
- **WHEN** 用户在侧栏搜索本地对话标题
- **THEN** 系统显示匹配的真实本地历史，打开结果导航到该对话，不插入截图中的示例历史

#### Scenario: 历史排序
- **WHEN** 用户选择标题排序或最近更新
- **THEN** 侧栏以所选顺序显示真实历史，不改写对话保存的更新时间

### Requirement: 随机欢迎语
系统 SHALL 在新对话首页从符合本地时段的句池中随机呈现欢迎语，深夜句池包含“深夜即兴时刻。”，并保持与参考图相同的文字位置和视觉层级。

#### Scenario: 进入新对话
- **WHEN** 用户首次访问、刷新或重新进入新对话首页
- **THEN** 系统抽取一条符合当前时段的欢迎语，同一时段提供多条候选，不仅显示一个固定句子

#### Scenario: 编辑与菜单操作
- **WHEN** 用户输入文字、打开菜单或搜索历史
- **THEN** 当前欢迎语保持不变，不因普通界面更新闪动或重新随机

### Requirement: 消息渲染与复制
系统 SHALL 区分用户和助手消息，渲染 Markdown、列表、引用、表格及带高亮的代码块，并提供助手正文和代码块复制及中文结果提示。

#### Scenario: 富文本回答
- **WHEN** 回答包含表格、列表和带语言标记的代码块
- **THEN** 系统保留结构，代码高亮且能复制原始代码，正文复制保留原始 Markdown

#### Scenario: 复制失败与不完整内容
- **WHEN** 剪贴板不可用或流式回答中的代码围栏尚未闭合
- **THEN** 复制失败显示可理解的中文提示，不完整 Markdown 仍可阅读且不导致页面崩溃

### Requirement: 流式滚动控制
系统 SHALL 在用户位于对话底部时跟随新内容；用户向上滚动后停止跟随并显示“回到底部”按钮，点击后恢复跟随。

#### Scenario: 跟随回答
- **WHEN** 用户位于底部且流式内容继续增加
- **THEN** 系统持续展示最新内容，不遮挡输入框

#### Scenario: 阅读历史内容
- **WHEN** 用户向上滚动离开底部且新内容继续输出
- **THEN** 系统不强制拉回底部，用户点击“回到底部”后跳到底部并恢复跟随

### Requirement: 可访问交互与反馈
系统 SHALL 为图标按钮提供中文可访问名称，支持键盘操作、可见焦点、侧栏抽屉及弹窗的焦点管理，并以中文表达加载、空状态和错误。

#### Scenario: 键盘使用
- **WHEN** 用户仅通过键盘打开抽屉或对话管理弹窗
- **THEN** 焦点进入弹层并受约束，Escape 关闭后焦点回到触发控件

#### Scenario: 页面加载与错误
- **WHEN** 对话详情正在加载或接口返回失败
- **THEN** 系统分别显示加载反馈或带重试操作的错误反馈，不伪装成空对话
