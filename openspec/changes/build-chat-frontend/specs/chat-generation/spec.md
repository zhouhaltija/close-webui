# Spec Delta

## Purpose

定义通过统一接口进行消息生成的外部行为，使独立 Mock 前端具备真实聊天所需的流式输出、取消和故障恢复能力。统一事件语义与可重复测试场景，让后续模型后端接入时能够保持既有用户体验，并避免重复发送和跨对话内容污染。

## ADDED Requirements

### Requirement: 统一接口边界
系统 SHALL 通过统一 HTTP API 管理对话并生成消息，使用内容增量、完成和错误事件表达生成过程；首版数据来自本地 Mock，不调用真实模型。

#### Scenario: 独立运行
- **WHEN** 用户在未配置后端或模型密钥的情况下启动前端
- **THEN** 对话管理与模拟回答可用，无请求被发送至外部模型服务

#### Scenario: 接口替换
- **WHEN** 后续服务提供相同 API 和事件语义
- **THEN** 页面和消息组件无需绑定提供商 SDK 即可使用统一客户端访问服务

### Requirement: 流式回答生命周期
系统 SHALL 将用户消息与助手回答分开保存，按顺序追加内容增量，展示等待和生成状态，收到完成事件后结束生成并保存完整内容。

#### Scenario: 正常生成
- **WHEN** 用户发送有效消息且 Mock 正常返回
- **THEN** 用户消息仅插入一次，助手先显示等待状态，再逐步展示回答，完成后恢复可发送状态

#### Scenario: 异常结束
- **WHEN** 流在完成事件前意外关闭或收到无效事件
- **THEN** 系统保留已有内容、将回答标记为失败并提供重试，不将其标记为成功

### Requirement: 单请求约束
系统 SHALL 在同一应用页面内最多允许一个等待或生成中的请求，阻止重复点击、重复 Enter 和并发重试产生额外消息或请求。

#### Scenario: 生成中重复发送
- **WHEN** 用户在等待或流式输出期间尝试再次发送
- **THEN** 系统不追加新消息且不创建第二个请求，停止操作仍可用

### Requirement: 取消生成
系统 SHALL 支持通过取消信号停止请求，在用户点击停止或离开当前对话时立即结束活动状态，保留已收到内容并忽略取消后的事件。

#### Scenario: 主动停止
- **WHEN** 用户在首个内容到达前或流式输出中点击停止
- **THEN** 系统取消请求，将助手消息标记为已停止，即使内容为空也显示状态，并恢复发送能力

#### Scenario: 迟到内容
- **WHEN** 已取消的请求随后仍产生内容或完成事件
- **THEN** 系统不追加内容、不改变已停止状态，也不影响其他对话

### Requirement: 失败与重试
系统 SHALL 在请求或生成失败时显示中文错误反馈并保留用户输入或已提交消息及部分回答，允许重试失败的最后一条回答而不重复插入用户消息。

#### Scenario: 生成失败后重试
- **WHEN** 最后一条助手回答失败且用户点击重试
- **THEN** 系统以同一用户消息重新生成，替换失败回答的内容和状态，不增加用户消息或另一条助手消息

#### Scenario: 提交前失败
- **WHEN** 对话创建或用户消息提交未成功
- **THEN** 系统保留可重新发送的输入，结束等待状态并显示错误，不显示未提交的消息为成功

#### Scenario: 失败回答不再是最后一条
- **WHEN** 用户在失败后发送了新的消息
- **THEN** 旧失败回答仍可阅读，但不再提供重试入口，避免改变后续消息上下文

### Requirement: 可重复 Mock 场景
系统 SHALL 提供固定的正常、慢速及失败场景，允许开发与验收通过明确配置选择场景，刷新或重复测试时不依赖随机结果。

#### Scenario: 正常与慢速
- **WHEN** 开发者选择正常或慢速场景后发送消息
- **THEN** 系统返回相同的固定回答内容，慢速场景以更长等待和增量间隔展示该内容，便于验收停止和滚动

#### Scenario: 失败恢复
- **WHEN** 开发者选择失败场景并发送消息后点击重试
- **THEN** 初次生成在固定内容位置失败，同一回答的首次重试成功完成，便于验证部分保存与无重复消息
