# Proposal

## Why

多供应商后端基线已经提交为 `29483aa`，但用户实际使用发现模型菜单偏离原设计、账号菜单点击范围过小、供应商与模型配置割裂、能力发现缺少回退，以及发送等待和流式卡顿。现有功能测试通过不能替代这些交互和性能验收，需要单独修复并提供可复核证据。

## What Changes

- 真实模型选择恢复输入框旁的下拉菜单和思考子菜单，沿用原模型菜单几何与交互，不再用居中弹窗。
- 账号菜单整行可点击，并验证键盘与触屏操作。
- 供应商页改为分类导航、供应商列表、当前供应商详情；添加入口移入供应商列表顶部，基础配置与所属模型列表同页操作。
- 模型发现形成上游列表、内置版本化目录、手动输入的回退链；保存后自动尝试发现，支持批量添加和启停，不要求逐个填写已知模型。
- 补全经过核实的模型与供应商准确别名映射，保留上游能力元数据，自动填写合法输出默认值并呈现原生思考控制；未知能力不猜测。
- 发送立即显示本地用户消息和提交状态；减少冗余请求及串行数据库往返，保留失败恢复、提前停止及身份隔离。
- 优化保存后发送的流式管线和增量渲染，增加可重复的延迟、长回答、停止及恢复验收，不把上游思考时间当作界面冻结。

## Capabilities

### New Capabilities

- `provider-workspace`: 供应商上下文中的配置与模型管理、账号菜单命中区域、真实模型下拉选择。
- `model-discovery-catalog`: 模型发现、内置目录回退、准确能力映射、默认值与来源管理。
- `chat-responsiveness`: 即时提交反馈、可靠持久化流式输出和可测量的渲染响应。

### Modified Capabilities

当前没有已归档的主规格。上述能力细化已有后端变更的交互与性能；已有用户隔离、停止、重试、保存后发送契约继续适用。用户本次明确要求覆盖原居中模型弹窗和分离配置流程。

## Impact

涉及 React 设置与菜单、生成协调器、Markdown 渲染、Go 模型发现/能力注册表、生成 SQL 和测试。新增目录接口及发现响应扩展须同步前后端契约；若需要数据库字段，追加 goose 迁移并重新生成 sqlc，不改已执行迁移。当前仅生成方案与实施提示词，任务保持未勾选，由另一智能体实施，再交原协作者审核。不导入用户截图或私人数据，不调用付费上游，不提交或推送后续修复，除非用户另行要求。
