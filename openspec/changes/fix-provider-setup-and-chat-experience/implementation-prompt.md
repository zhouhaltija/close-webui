## 六项必须交付的修复

1. **恢复原模型菜单。** 参考 `test-results/screenshots/model-effort-menu.png`，复用 `src/components/ModelSelector.tsx` 的 Dropdown/Sub/CSS。真实模型用当前用户启用列表，显示名称/说明/勾选；原生思考控制放子菜单。不要再用居中 Dialog，不恢复假模型或通用假档位。保持草稿、切换默认参数、鼠标跨子菜单、移动边界与 Escape 焦点恢复。
2. **账号菜单整行可点。** `Auth.tsx` 的设置 Link 经 asChild 是 inline 菜单项，样式没有整行块级布局。修正实际命中区域。测试点击左/中/右空白和内边距，不能只用 locator 点击文字中心。
3. **供应商页按上下文重做。** 桌面左侧设置分类，旁边供应商列表，列表顶部添加按钮；右侧上部为选中供应商基础配置，下部为所属模型和拉取按钮。手机列表/详情逐级切换。模型可同页批量添加/启停、设默认和配置思考；“模型”分类用于全局汇总，不能再强迫跨页重新选一次供应商。迟到请求、未保存草稿、错误和密钥保留都要处理。
4. **自动能力与三层回退。** 上游发现模型 → 用准确内置目录补能力/缺失项；发现失败或空列表 → 当前供应商兼容内置目录；均不可用才手动 ID。多数 `/models` 不返回完整思考能力，目前 DiscoveredModel 只保留 ID/name，注册表也无法枚举候选。建立版本化目录与统一解析，已知候选直接显示能力并自动填合法默认值，默认思考沿用供应商 `{}`。精确核实截图的硅基流动 `zai-org/GLM-5.3-Flash` 及其参数映射，不能任意去前缀/折叠大小写/猜名称。目录候选不代表该账号已获权限，401/403 必须明确提示。保留用户已有设置，不静默降档或替换默认模型。
5. **发送立即有反馈。** 当前 generation.ts 先建对话、导航到空页，再等 generate 响应头才插消息。分离本地提交预览与已确认消息，点击后 100ms 内显示用户消息和助手提交状态。慢创建/慢提交都不能闪空页；成功按原 ID 合并，失败恢复草稿、不确定提交先对账，停止/退出/删除不能复活迟到预览。
6. **消除可测的人为流式停顿。** 当前每批先 BEGIN、两 UPDATE、COMMIT，再发送；数据库只读实测单往返约 90.2ms，四语句约 375ms（不是完整生成实测）。减少到单条原子 SQL，保留 user/conversation/generation/assistant/活动状态条件。分离有界积累与单写入协调，首段不等大批次，终结必须排空并先保存终态。前端帧合并只刷新活动消息，避免整段历史 structuredClone、排序和 Markdown/Shiki 重复工作。用固定仿真和真实独立 schema 量化改进，不用假打字或内存假持久化掩盖卡顿。
