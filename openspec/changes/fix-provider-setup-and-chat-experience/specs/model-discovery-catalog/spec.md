# Spec Delta

## Purpose

定义供应商模型发现和内置模型能力目录的衔接，使用户优先选择已发现或已登记型号，并自动获得准确能力、合法默认值与来源，只有两种途径均不可用时才需要手动填写。

## ADDED Requirements

### Requirement: 上游能力与输出限值持久化
系统 MUST 解析正式支持的上游模型元数据，区分上下文、模型最大输出及用户回复上限，并持久保存服务端验证后的公开字段，使发现、添加、刷新、保存与生成请求使用一致的能力约束。

#### Scenario: 原生响应与合法交集
- **WHEN** Anthropic、Gemini、OpenRouter 或普通 OpenAI 兼容协议返回明确支持字段、缺失字段或相互冲突的限值
- **THEN** 严格按协议及适配白名单解析，保留原始调用 ID，可信上限与内置约束取合法交集；无效字段被忽略，未知思考参数不推断，不能把上下文当成输出限值

#### Scenario: 添加后刷新与重启
- **WHEN** 模型添加、重新读取、能力刷新或服务重启
- **THEN** 已发现的合法限值及思考状态仍可用，用户合法偏好被保留；已有设置不兼容时明确提示而不静默降低，生成阶段不能再退回另一套静态限值

#### Scenario: 配置变化与能力伪造
- **WHEN** 供应商地址、协议、适配或密钥变化，旧发现返回迟到，或客户端伪造能力字段
- **THEN** 旧配置元数据不会应用到新配置，客户端不能扩大合法能力，用户之间的发现与持久化元数据严格隔离

### Requirement: 模型发现与回退
系统 SHALL 保存供应商后自动尝试发现一次并提供重新拉取；上游失败、不支持或返回空列表时提供与该供应商配置兼容的内置模型候选，始终标明候选来源和失败原因。

#### Scenario: 上游发现成功
- **WHEN** 上游返回模型 ID 及可识别能力元数据
- **THEN** 保留准确 ID，按协议解析受支持字段，并用经过核实的内置能力补全缺失项，显示候选供用户批量添加

#### Scenario: 失败及空列表
- **WHEN** 上游模型接口不可用、超时、空列表或凭据无效
- **THEN** 配置和已添加模型保留；说明实际错误，显示内置候选而不伪称连接成功或账号已获得这些型号权限

#### Scenario: 无匹配内置项
- **WHEN** 上游发现不可用且内置目录没有兼容候选
- **THEN** 提供手动填写准确模型 ID 的入口，允许普通文本聊天，未核实的思考能力不展示

### Requirement: 准确能力与参数适配
系统 MUST 通过协议、供应商适配和准确型号或明确登记别名确定能力；原始调用 ID 与内部规范身份分开，不根据名称片段、任意前缀删除或大小写折叠推测支持。

#### Scenario: 聚合站别名
- **WHEN** 发现已核实的供应商命名空间型号，包括硅基流动的 GLM 型号
- **THEN** 自动关联该供应商支持的原生思考参数并保持原调用 ID；字段名、档位和预算遵守该供应商已核实约定

#### Scenario: 未核实别名与冲突
- **WHEN** 型号仅与已知型号拼写相似，或可信上游限值与内置限制冲突
- **THEN** 不继承未经核实能力；冲突采用合法交集或报告配置不兼容，不放宽参数限制，不静默改写用户已保存档位

### Requirement: 自动默认值与显式覆盖
系统 SHALL 在添加已知模型时自动填写显示名和合法输出默认值，默认思考行为沿用供应商；用户可以在当前供应商模型行编辑原生设置，无需先保存再进入另一页才能看到能力。

#### Scenario: 默认添加与自定义
- **WHEN** 用户添加或批量启用已知候选模型
- **THEN** 不要求重复输入 ID、名称、输出值或选择通用参数适配；强制思考模型没有关闭项，保存的显式设置优先且经后端校验

#### Scenario: 刷新能力
- **WHEN** 刷新模型列表或内置能力目录版本发生变化
- **THEN** 不清除已添加模型、默认模型及用户覆盖；不兼容设置明确标记，允许主动恢复供应商默认

### Requirement: 版本与审查来源
系统 SHALL 为内置条目维护目录版本、核实日期、模型来源、供应商参数来源和默认行为；运行时无需依赖外部目录服务才能配置已知模型。

#### Scenario: 检查与离线回退
- **WHEN** 上游发现失败或审查者检查能力设置
- **THEN** 内置目录仍可用，能力来源和核实版本可追溯，未经真实调用验证不得被标成已通过实网冒烟
